# 16 KB page alignment

Builds apply `io.github.supermonster003.autojs6-native-alignment:1.8.0`. Every assembled APK
is checked and reports are written to `app/build/reports/native-alignment/`.
Use `:app:verifyNativePageAlignment` to recheck existing artifacts.

The gate enforces ELF PT_LOAD alignment for arm64-v8a and x86_64. Uncompressed `.so` entries also require 16 KB ZIP alignment. Third-party 32-bit alignment is advisory.

Every native dependency or toolchain upgrade must pass the gate again. Static alignment
does not prove runtime behavior: test on a device reporting `getconf PAGE_SIZE = 16384`
with compatibility mode disabled. No `android:pageSizeCompat` override is permitted.

中文: 构建门禁检查全部产物并输出 JSON 报告. 原生依赖或工具链升级后必须重新校验,
且需在页大小为 16384 的设备上关闭兼容模式后执行运行时验证.

[Deployment and device acceptance matrix](https://github.com/SuperMonster003/AutoJs6/blob/master/docs/dev/page-size-16kb-roadmap.md)

ABI packaging: the app splits and plugin metadata include `arm64-v8a`,
`armeabi-v7a`, `x86`, and `x86_64`. The existing
`com.google.mlkit:text-recognition-chinese:16.0.1` dependency resolves
`text-recognition-bundled-common:17.0.0`, whose AAR already provides
`libmlkit_google_ocr_pipeline.so` for all four ABIs. The universal APK already
included x86; the x86 split and advertised ABI now match that native inventory.
Run `:app:assembleRelease` and `:app:verifyNativePageAlignment` after ABI changes,
and verify recognition through the host on the new target ABI.
